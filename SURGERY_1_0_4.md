# SURGERY EQ 1.0.4

Starts from PR #17 / improve/surgery-eq-quality-pass HEAD f6f1fb2db3ebe26a5f16f250b4d5c1ca1b7824f1 (1.0.3), verified against origin and GitHub before edits.

Changes: approved B+C muted spectral heat (smoky burgundy/amber, graphite/teal/violet), restrained pale rose-white trace, unchanged individually coloured ROOT markers/territories. FAST 4:1 replaces the displayed FET 4:1 label, retaining index 4 and its processing. Dropdowns use consistent 13-unit typography, graphite background, cyan selected row/tick, owning-component anchoring and JUCE screen-edge/scale handling. Below is preferred with automatic above fallback.

Rendering: cache the static hardware background per editor size/tab; reuse unchanged CARVE response paths and raster overlays with parameter/size/sample-rate/selection invalidation; batch the 256 gradient strips into a reusable 256x64 spectral colour image clipped to the same real FFT envelope. Unchanged presentation and settled analyzer frames do not request redundant graph paints. Display smoothing still advances at 1/60 s, with the existing memory law. No FFT or audio computation was added to paint. No audio callback was changed.

Compatibility: all parameter IDs/types/order/ranges/defaults and state schema remain unchanged. PluginProcessor.cpp differs only in the two choice labels; audio engines, FFT/measurement code, spectrum decay, frequencies and response math are unchanged. Chassis PNG is byte-identical to 1.0.3. Legacy theme parameter remains inert; ONYX is the only UI. The VST3 filename and identity remain SURGERY EQ v1.0.vst3; software/editor version becomes 1.0.4. ROOT compression still starts OFF/0 dBFS, the CARVE trigger parameter remains hidden, and recalled parameters remain intact.

Verification: use the clean Windows Actions build, all 18 CTest suites and pluginval strictness 8. GUI tests render all four tabs and 100/125/150% scales; exercise native dropdowns and selected states near normal/lower-screen positions; check compatibility and host parameter notifications; benchmark changing spectrum frames with one/two instances and finite audio processing. CSV timing evidence is graph-paint/update wall time and Windows GUI-thread CPU cost, not compositor FPS. Test images use deliberate non-factory settings.

Limitations: a 60 Hz request is not a guarantee of 60 displayed FPS. Software rendering cost grows with scaling/instance count. The benchmark excludes compositor/host scheduling and does not certify FL Studio window movement, physical monitor DPI changes, listening performance or real production project files. Existing state round-trip tests and pluginval GUI/automation checks complement, but do not replace, user verification in FL Studio. Unsigned development build. PR remains draft and unmerged.
